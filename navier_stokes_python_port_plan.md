# Python Port Plan: ROL Dynamic Navier-Stokes Reduced Objective

## Goal

Create a Python class for the objective built in:

`rol/example/PDE-OPT/dynamic/navier-stokes/objective.cpp`

The class should be callable from Python and provide:

```python
obj = NavierStokesReducedObjective.from_xml("rol/example/PDE-OPT/dynamic/navier-stokes/input.xml")
f = obj.value(z)
g = obj.gradient(z)
hv = obj.hess_vec(z, v)
```

The desired object is the reduced dynamic objective: each call treats the control time history `z` as the optimization variable, solves the Navier-Stokes state equation forward in time, and computes value, gradient, or Hessian-vector products with adjoint and sensitivity solves.

## What `objective.cpp` Builds

`objective.cpp` does not contain most of the objective math. It wires together:

1. XML parameters from `input.xml`.
2. Mesh from `channel.txt`.
3. `DynamicPDE_NavierStokes`.
4. `DynConstraint`.
5. State/control/residual vectors.
6. Integrated QoIs:
   - `QoI_State_NavierStokes`, default `Dissipation`.
   - `QoI_DownStreamPower_NavierStokes`.
   - `QoI_RotationControl_NavierStokes` if parametric control is enabled.
   - `QoI_L2Penalty_NavierStokes` if field boundary control is enabled.
7. Final-time QoI:
   - `QoI_State_NavierStokes`, default `Tracking`.
8. `LTI_Objective`, which applies theta-rule time quadrature and final-time objective logic.
9. `ROL::ReducedDynamicObjective`, which performs the forward state solve, adjoint solve, and Hessian-vector solve.

The default XML has:

- `Use Parametric Control = true`
- `Reynolds Number = 200.0`
- `End Time = 20.0`
- `Number of Time Steps = 800`
- `Theta = 1.0`
- integrated objective type `Dissipation`
- final-time objective type `Tracking`
- state cost, downstream boundary cost, final-time state cost all equal to 1
- control cost equal to 0

## Recommended Python Stack

Use a fidelity-first stack:

- `numpy` for local element calculations and vector operations.
- `scipy.sparse` for global sparse assembly.
- `scipy.sparse.linalg` for sparse direct or iterative linear solves.
- `xml.etree.ElementTree` or `defusedxml` for parsing `input.xml`.
- A custom parser for `channel.txt`, because the C++ `MeshReader` reads ASCII text generated by `ncdump` from an Exodus mesh.
- `pytest` for regression and derivative tests.

Avoid switching directly to FEniCS/dolfinx for the first pass unless discretization drift is acceptable. The C++ code uses Intrepid-style Q2/Q1 finite elements and custom assembly. A FEniCS port would be cleaner in Python but would not be a close numerical port.

## Implementation Phases

### Phase 1: Configuration and Mesh

Implement:

- XML parameter reader.
- `MeshReader` equivalent for `channel.txt`.
- Extraction of:
  - `coordx`, `coordy`
  - `connect1`
  - side sets `elem_ss*`, `side_ss*`
  - number of nodes, elements, side sets, dimension

Mirror the C++ `MeshReader` behavior, not a generic Exodus import.

### Phase 2: Finite Element Layer

Port enough of Intrepid/FE behavior to support this problem:

- Q2 velocity basis on quadrilateral cells.
- Q1 pressure basis on quadrilateral cells.
- Quadrature degree 4 by default.
- Boundary quadrature degree 4 by default.
- Cell Jacobians, determinants, inverse Jacobians.
- Basis values and gradients on volume and boundary quadrature.
- Local mass/stiffness-like matrices where needed.
- Local-to-global field pattern for `[u_x, u_y, p]`.

Important C++ source:

- `pde_navier-stokes.hpp` constructs Q2 velocity, Q1 pressure, and quadrature.
- `fe.hpp` provides evaluation and integration helpers used throughout QoIs and residuals.

### Phase 3: Steady Navier-Stokes Residual and Derivatives

Port `PDE_NavierStokes`:

- Residual:
  - viscosity term `nu grad u`
  - convection term `(u . grad)u`
  - pressure gradient term
  - incompressibility equation
- Jacobian with respect to state.
- Adjoint Hessian contribution with respect to state, needed for exact Hessian-vector products.
- Riesz maps only if the Python vector conventions need them.

Default viscosity is `nu = 1 / Reynolds Number`.

### Phase 4: Dynamic Constraint

Port `DynamicPDE_NavierStokes` and the relevant `DynConstraint` operations.

The dynamic residual is effectively:

```text
c_k(u_old, u_new, z_k)
  = M(u_new - u_old)
    + dt * ((1 - theta) * R(u_old, z_k) + theta * R(u_new, z_k))
```

plus boundary-condition overwrite logic.

Required methods:

```python
constraint.value(u_old, u_new, z_k, ts)
constraint.solve(u_old, z_k, ts, initial_guess=None)
constraint.apply_jacobian_uo(v, u_old, u_new, z_k, ts)
constraint.apply_jacobian_un(v, u_old, u_new, z_k, ts)
constraint.apply_jacobian_z(v, u_old, u_new, z_k, ts)
constraint.apply_adjoint_jacobian_uo(v, ...)
constraint.apply_adjoint_jacobian_un(v, ...)
constraint.apply_adjoint_jacobian_z(v, ...)
constraint.solve_jacobian_un(rhs, ...)
constraint.solve_adjoint_jacobian_un(rhs, ...)
constraint.apply_adjoint_hessian_*(...)
```

Start with the parametric control branch:

- Cylinder side set is side set 4 in the C++ code.
- Boundary values on the cylinder use:

```text
tx = y - cy
ty = cx - x
bc = [tx, ty] / r
u = z_param[0] * bc
```

For nonparametric boundary control, add the field-control branch later:

- `Jacobian_zf` applies `-I` on cylinder boundary velocity dofs.
- `QoI_L2Penalty_NavierStokes` provides the boundary L2 control penalty.

### Phase 5: Initial Condition

The C++ checks for:

```text
initial_condition_Re{int(Re)}.txt
```

If present, it loads that file. If not, it builds potential flow and runs a warm-up solve before writing the initial condition.

No matching `initial_condition_Re200.txt` was found in the repo during inspection, so the Python implementation needs one of these options:

1. Reproduce `PotentialFlow` from `initial_condition.hpp`, then implement the same warm-up solve.
2. Allow the user to pass an initial condition file.
3. Generate and cache the initial condition from Python.

The safest first implementation is option 2 plus option 1 as fallback.

### Phase 6: QoIs

Port the QoIs used by `objective.cpp`.

Integrated objective:

```text
w1 * StateQoI(integrated_type)
+ w2 * DownStreamPowerQoI
+ w3 * ControlQoI
```

Final-time objective:

```text
wT * StateQoI(final_time_type)
```

Default QoIs:

- `Dissipation`
- `DownStreamPower`
- `RotationControl`
- `Tracking`

Implement value, gradient, and Hessian-vector contributions for each.

Important default simplification:

- `Control Cost = 0` in `input.xml`, so `RotationControl` has zero contribution by default. Still implement it because the class should honor modified XML weights.

### Phase 7: LTI Objective

Port `LTI_Objective`.

For each time interval `[t_old, t_new]`:

```text
f_k = dt * ((1 - theta) * obj_k(u_old, z_k)
            + theta * obj_k(u_new, z_k))
      + final_time_obj(u_new, z_k) if t_new == T
```

Also port:

- `gradient_uo`
- `gradient_un`
- `gradient_z`
- all `hessVec_*_*` methods

These methods are needed by the reduced objective recurrences.

### Phase 8: Reduced Objective

Port the non-sketching path of `ROL::ReducedDynamicObjective` first.

Do not implement sketching initially. The default XML has `Use Sketching = false`, so full state and adjoint histories are stored.

#### Value

Algorithm:

1. Set `u_hist[0] = u0`.
2. For `k = 1 ... nt - 1`:
   - solve `c_k(u_hist[k-1], u_hist[k], z[k]) = 0`
   - add `dynamic_objective.value(u_hist[k-1], u_hist[k], z[k], ts[k])`
3. Return accumulated value.

#### Gradient

Algorithm:

1. Solve state if needed.
2. Terminal adjoint:

```text
lambda_N = J_un^{-T} f_un
```

3. For reverse time:

```text
rhs = f_uo - J_uo^T lambda_next
lambda_k = J_un^{-T} (rhs + f_un)
```

4. Per interval gradient:

```text
g_k = f_z - J_z^T lambda_k
```

5. Set `g[0] = 0` to match ROL's unused zeroth interval.

#### Hessian-Vector Product

Algorithm:

1. Solve state and adjoint if needed.
2. Forward state sensitivity:

```text
w_0 = 0
w_k = J_un^{-1} (J_z v_k - J_uo w_{k-1})
```

3. Initialize each HVP block with the control-control Hessian of the Lagrangian.
4. Add mixed state/control Hessian terms.
5. Solve adjoint sensitivity backward.
6. Add `J_z^T p_k` adjoint-sensitivity contributions.
7. Set `hv[0] = 0`.

Mirror helper routines from `ROL_ReducedDynamicObjective.hpp`:

- `advanceStateSens`
- `setTerminalConditionHess`
- `computeOldStateHessLag`
- `computeOldMixedHessLag`
- `computeNewStateJacobian`
- `computeNewStateHessLag`
- `computeNewMixedHessLag`
- `computeControlHessLag`
- `addMixedHessLag`
- `addAdjointSens`

## Validation Plan

### Unit Tests

Test each layer:

1. Mesh parser:
   - counts match `channel.txt`
   - coordinates and connectivity match C++ reader expectations
   - side sets are parsed correctly

2. FE layer:
   - partition of unity
   - gradient transformations
   - mass matrix symmetry
   - positive quadrature weights and determinants

3. PDE residual:
   - finite-difference check of state Jacobian
   - adjoint consistency: `<Jv, w> = <v, J^T w>`

4. QoIs:
   - gradient directional checks
   - Hessian-vector directional checks

5. Reduced objective:
   - gradient check:

```text
(F(z + eps v) - F(z - eps v)) / (2 eps) ~= <grad F(z), v>
```

   - HVP check:

```text
(grad F(z + eps v) - grad F(z - eps v)) / (2 eps) ~= H(z) v
```

   - symmetry check:

```text
<v, H w> ~= <w, H v>
```

### C++ Regression Oracle

Prefer creating a temporary C++ or pybind reference harness around the existing ROL object to compare:

- objective value
- gradient
- Hessian-vector products

Use small `nt` values first to keep test runtime sane.

## Risks And Notes

- The hardest part is not the reduced objective algorithm. It is faithfully reproducing the finite-element assembly and boundary-condition overwrite semantics.
- The default problem has 800 time steps and a fairly large mesh. Start with a reduced XML for tests.
- Exact Hessian-vector products require second-order Lagrangian terms from both the QoIs and the dynamic constraint.
- Since `Use Sketching = false` by default, skip sketching in the first implementation.
- Since `Use Parametric Control = true` by default, implement scalar rotation control first.
- Implement nonparametric boundary control after the default path passes derivative checks.

## Suggested First Milestone

Build a reduced-size Python prototype that:

1. Parses XML and mesh.
2. Builds Q2/Q1 FE data.
3. Solves a single dynamic Navier-Stokes step for scalar rotation control.
4. Evaluates the integrated objective for that step.
5. Passes finite-difference checks for that one-step value and gradient.

After that, extend to full time history, adjoint gradient, and HVP.
